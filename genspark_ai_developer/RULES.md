# RULES.md — القاعدة الذهبية (دستور العمل من Phase 11 فصاعدًا)

هذه القواعد ملزمة لكل chunk في هذا المستودع. أي مخالفة = إيقاف العمل وتصحيح المسار.

## 1. صفر قبول أعمى (Zero Blind Acceptance)
- أي ادعاء تقني (من gist، من تعليق، من ذاكرتي) يُعامل كفرضية حتى يُثبت عمليًا في الكود أو الـDOM أو الـsuites.
- مثال ملزم: ادعاء «سبب بعثرة RTL هو inline-block + الأرقام» -> يُعاد إنتاجه في Chromium ويُقاس بـgetBoundingClientRect قبل اختيار أي إصلاح.
- الحلول المقترحة في أي مصدر تُختبر واحدة واحدة؛ ما لا يثبت لا يُدمج.
- كل بحث خارجي يُوثّق بروابطه ونتيجته الفعلية (ما قرأناه، لا ما توقعناه) في `workspace--RESEARCH/RESEARCH.md`.

## 2. صفر تخمين (Zero Guesswork)
- إذا كان المطلوب غامضًا أو متعارضًا: توقّف واسأل، لا تخترع تفسيرًا.
- لا نغيّر سلوكًا قائمًا (سكور/قلوب/mastery/telemetry) دون اختبار يغطي السلوك القديم والجديد.
- كل تغيير في UI يُثبت بـDOM assertion وليس بمعاينة بصرية فقط.

## 3. الروح التربوية (Warm Pedagogy لطفل في الصف الثالث)
- الخطأ فرصة تعلم: لا كشف للإجابة الصحيحة عند أول خطأ؛ تشجيع دافئ ثم شرح ثم إعادة محاولة.
- لغة مصرية دافئة بسيطة، جمل قصيرة، لا فصحى إخبارية جافة.
- الاحتفال الأكبر يُمنح لمن تعلّم من غلطه وحلّها بنفسه.

## 4. قيود هندسية ثابتة
- ممنوع منعًا باتًا توليد ملف صوت **لكل مسألة أو لكل جملة شرح كاملة** (4,813 جملة ≈ 77MB — مقاس في Phase 13). ~~الصوت إما مولّد لحظيًا (Web Speech / Web Audio) أو من أصول قليلة جدًا موجودة أصلًا.~~ **عُدّل في Phase 13-14 باعتماد المالك** (gists 165f815b و 5e7813f5 و 13c2784a) لأن Web Speech ثبت صمته على هاتف المالك (Android بلا حزمة عربية):
  - **معمارية الصوت المعتمدة (ثابتة):** مقاطع مسجّلة مُجمّعة (Concatenative) = مقاطع ثابتة + أرقام 1..100 تُركّب وقت التشغيل على عنصر `<audio>` واحد (لا Web Audio: يُكتم بمفتاح الصامت على iOS)، ثم `speech.js` كرجوع، ثم التظليل البصري. عبارات التشجيع جمل كاملة قصيرة (نبرة عاطفية متصلة) لأنها عدد محدود.
  - كل نص يُنطق له مقطعه؛ `phase13_voice.py` يفشل إن ظهر نص شرح بلا مقطع، و`phase14_cheers.py` يفشل إن تغيّر نص عبارة دون إعادة تسجيلها (hash).
  - المفتاح في `.env` فقط (غير مرفوع). التوليد وقت البناء (`tools/build_explain_audio.py`، `tools/build_cheers_audio.py`)، لا في المتصفح أبدًا.
- ممنوع تعديل الملفات المحمية: `plant.html`, `math.html`, `albayyinah.html`, `quran-alqadr/index.html` (تحقق sha256 قبل كل PR).
- Zero-Emoji في الكود والوثائق (أسهم ASCII `->` / `<->`).
- `README.md` الجذر: إضافة فقط (append-only) في نهاية كل Phase.
- push-per-chunk: كل خطوة صغيرة تُدفع فورًا؛ `PROGRESS.md` هو مرساة الاستئناف.

## 5. إجراء التسليم لكل Phase
1. تجميد الخطة في `PROGRESS.md` (K0) قبل أي كود.
2. chunk -> اختبار -> commit -> push.
3. كل الـsuites PASS + sha256 المحميات + bump نسخة.
4. squash لكوميت واحد فوق `origin/main` -> PR عبر GitHub API -> رابط PR في PROGRESS.

## 6. الميثاق التربوي والإيماني (Phase 14)
- المرجع: `PROJECT_VISION.md` في جذر المستودع (أضافه المالك). يُقرأ قبل أي محتوى يُعرض أو يُنطق للطفل، ولا يُعدَّل إلا بطلب المالك.
- **النصوص الشرعية:** لا يُنسب نص للنبي صلى الله عليه وسلم أو لصحابي أو إمام إلا نص مشهور صحيح، مع حقل `src` (المصدر ورقم الحديث/الآية، مُتحقَّق بالبحث) و`review: true` (يظهر للأب «يحتاج مراجعتك»). المنطوق من حقل `say` **بالتشكيل الكامل**: بدون تشكيل قرأ المحرك «وقل» -> «وقال»/«لربي» (مُقاس بالتفريغ). **كل** عبارة شرعية جديدة تُفرَّغ صوتيًا كاملة قبل الدمج — لا عيّنات.
- **مخاطبة الطفل بجنسه:** عبارة فيها فعل أو ضمير مذكّر/مؤنث لا تكون `all`؛ لها نسخة لسليم وتوأم مؤنث `<id>g` لكارما وكندة. الاسم كما في `store.js`: «كندة».
- **الإخوة فريق واحد:** التشجيع يذكر الإخوة بالمحبة والتعاون، لا بالمقارنة أو التفضيل.
- **كل صوت بشري مكتوب:** يظهر نصه (subtitle) ويُسجَّل في «سجل الكلمات المنطوقة» بلوحة الأب مع «نسخ النص».
- **لا أرقام غير مُثبتة في الوثائق** (مثل «90% من الهواتف»): المثبت فقط، مع مصدره.
